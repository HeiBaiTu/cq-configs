## 设置哪些怪物可以被诱惑

### 方法1: 修改怪物标志

要让某个怪物可以被诱惑，需要确保其 `flagid` 对应的标志中**没有** `DenyBeCatch = true`：

```lua
-- 在Monster.config中修改怪物的flagid
[怪物ID] = {
    flagid = 9,  -- 使用flagid=9，这个标志没有DenyBeCatch限制
    -- 其他配置...
}
```

### 方法2: 修改标志配置

在 `Flags.config` 中创建新的标志或修改现有标志：

```lua
[20] = {
    id = 20,
    DenyAutoAddMp = true,
    DenyDieSubExp = true,
    -- 注意：这里没有 DenyBeCatch = true
    -- 所以使用此标志的怪物可以被诱惑
    AttackPet = true,
    noReturnHome = true,
}
```

### 方法3: 修改技能条件

在 `SkillRanges.config` 中修改诱惑条件：

#### 降低攻击力限制
```lua
[95] = {
    conds = {
        {cond=1,value=1},    -- 保持等级限制
        {cond=8,value=0},    -- 降低攻击力限制到0，允许诱惑所有怪物
    },
}
```

#### 完全移除条件限制
```lua
[95] = {
    conds = {},  -- 移除所有条件限制
}
```

#### 添加更多限制条件
```lua
[95] = {
    conds = {
        {cond=1,value=1},     -- 等级 ≥ 1级
        {cond=8,value=30},    -- 物理攻击 ≥ 30点
        {cond=9,value=20},    -- 魔法攻击 ≥ 20点
    },
}
```

## 注意事项

### 1. 技能平衡性
- 诱惑宠物是强力技能，需要合理设置学习等级和冷却时间
- 考虑是否会影响游戏平衡，法师原本没有召唤类技能
- 建议设置合理的宠物数量限制

### 2. 职业特色
- 诱惑宠物技能原本可能是法师的专属技能
- 考虑是否要限制其他职业使用此技能

### 3. 怪物平衡
- 允许诱惑的怪物类型需要平衡考虑
- 避免诱惑过于强力的怪物影响游戏平衡

### 4. 同步性要求
- 前后端配置必须保持同步
- 前端修改后需要清除浏览器缓存
- 后端修改后需要重启服务器

### 5. 测试验证
- 修改后需要同时测试前后端功能
- 确认技能学习和使用正常
- 验证诱惑效果符合预期

## 总结

诱惑宠物技能的配置涉及多个层面的限制：

1. **技能层面**: 通过 `SkillRanges.config` 中的条件限制 (等级、攻击力)
2. **怪物层面**: 通过 `Flags.config` 中的 `DenyBeCatch` 标志限制
3. **职业层面**: 通过 `Skills.config` 中的 `vocation` 限制

通过合理配置这些限制条件，可以实现为法师开启诱惑宠物技能，并控制哪些怪物可以被诱惑，从而保持游戏的平衡性和趣味性。

修改时需要注意前后端配置的同步性，以及技能和怪物的平衡性，确保修改后的游戏体验符合预期。
