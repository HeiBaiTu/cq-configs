# 一键回收系统配置分析

## 概述
本文档详细分析游戏中的一键回收系统配置，包括前后端配置结构、智能回收功能，以及如何添加新的回收装备类型。

## 一键回收系统架构

### 系统组成
1. **手动一键回收**: 玩家手动触发，回收指定类型的装备
2. **智能回收**: 自动触发，当装备包裹达到100格时自动回收
3. **回收设置**: 玩家可配置哪些装备类型参与回收

## 如何添加新的回收装备类型

### 方法1: 添加新的装备等级分类

#### 1. 修改后端配置

在 `data/config/setting/RecyclingSetting.config` 中添加新的回收选项：

```lua
[1] = {
    -- 现有配置...
    [17] = {  -- 新的索引号
        id = 1,
        idx = 17,
        optionid = 62,  -- 新的选项ID
        value = 0,
        name = "新装备类型",
        tips = "回收背包中所有新装备类型",
        title = "装备回收",
        itemlevel = 114,  -- 新的装备等级标识
        showQuality = 4,
    },
}
```

#### 2. 修改前端配置

在 `split_configs/RecyclingSettingConfig.json` 中添加对应配置：

```json
{
  "1": {
    "17": {
      "id": 1,
      "idx": 17,
      "itemlevel": 114,
      "name": "新装备类型",
      "optionid": 62,
      "showQuality": 4,
      "tips": "回收背包中所有新装备类型",
      "title": "装备回收",
      "value": 0
    }
  }
}
```

#### 3. 设置装备的itemlevel

在 `data/config/item/StdItems.config` 中为新装备设置对应的 `itemlevel`：

```lua
[新装备ID] = {
    id = 新装备ID,
    name = "新装备名称",
    -- 其他配置...
    itemlevel = 114,  -- 设置为新的装备等级标识
    -- 其他配置...
}
```

## 配置参数说明

### 回收设置参数

| 参数名 | 类型 | 说明 |
|--------|------|------|
| id | 数字 | 回收分类ID，用于区分不同的回收分类 |
| idx | 数字 | 分类内索引，用于排序 |
| optionid | 数字 | 选项ID，用于客户端识别 |
| value | 数字 | 默认值，0=不回收，1=回收 |
| name | 字符串 | 显示名称 |
| tips | 字符串 | 提示信息 |
| title | 字符串 | 分类标题 |
| itemlevel | 数字 | 装备等级标识，用于匹配装备 |
| showQuality | 数字 | 显示品质，影响UI显示效果 |

### 装备等级标识规则

- **101-113**: 常规装备等级
- **65-99**: 神装等级
- **200+**: 自定义装备等级（建议使用）

## 修改步骤

### 1. 备份原文件
```bash
# 备份后端配置文件

cp data/config/setting/basicsSetting.config data/config/setting/basicsSetting.config.backup

# 备份前端配置文件
cp split_configs/RecyclingSettingConfig.json split_configs/RecyclingSettingConfig.json.backup

```

### 2. 修改后端配置
按照上述方案修改 `data/config/setting/` 目录下的配置文件

### 3. 修改前端配置
按照上述方案修改 `split_configs/` 目录下的配置文件

### 4. 设置装备等级
在 `data/config/item/StdItems.config` 中设置装备的 `itemlevel`

### 5. 重启服务器
让后端配置生效

### 6. 清除客户端缓存
让前端配置生效

### 7. 测试验证
在游戏中测试回收功能是否正常工作

## 注意事项

### 1. 配置同步性
- 前后端配置必须保持同步
- 前端修改后需要清除浏览器缓存
- 后端修改后需要重启服务器

### 2. 装备等级标识
- 确保 `itemlevel` 的唯一性
- 建议使用200+的数字作为自定义装备等级
- 避免与现有装备等级冲突

### 3. 选项ID唯一性
- 确保 `optionid` 的唯一性
- 建议使用100+的数字作为自定义选项ID
- 避免与现有选项ID冲突

### 4. 用户体验
- 合理设置默认值，避免误回收重要装备
- 提供清晰的提示信息
- 考虑装备的稀有度和价值

### 5. 性能考虑
- 避免设置过多的回收选项
- 合理设置回收触发条件
- 考虑服务器性能影响

## 总结

一键回收系统通过装备等级标识 (`itemlevel`) 来分类和管理可回收的装备，支持手动和自动两种回收模式。添加新的回收装备类型需要：

1. 在回收设置中添加新的选项配置
2. 为装备设置对应的 `itemlevel`
3. 确保前后端配置同步
4. 测试验证功能正常

通过合理配置回收选项，可以为玩家提供便捷的装备管理功能，提升游戏体验。
