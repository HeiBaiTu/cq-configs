# 前后端技能配置流程分析

## 概述
游戏采用前后端分离的配置架构，前端配置用于客户端显示和交互，后端配置用于服务器逻辑计算。

## 配置架构说明

### 前端配置 (split_configs/)
- **用途**: 客户端浏览器缓存和显示
- **格式**: JSON格式
- **位置**: `split_configs/` 目录
- **特点**: 数据经过压缩，浏览器解压后使用

### 后端配置 (data/config/)
- **用途**: 服务器端逻辑计算
- **格式**: Lua配置格式
- **位置**: `data/config/` 目录
- **特点**: 直接由服务器程序读取

## 召唤神兽技能配置流程

**文件**: `data/config/skill/Skills.config`

```lua
[30] = {

    skillType = 2,          -- 技能类型

    action = 2,             -- 动作类型

```

```lua
[223] = {
    id = 223,

    xEnd = 0,
    yStart = 0,
    yEnd = 0,
    rangeType = 6,           -- 范围类型
```

## 配置流程和关系

### 1. 数据流向
```
后端配置 (服务器逻辑)
    ↓
前端配置 (客户端显示)
    ↓
浏览器缓存和解压
    ↓
游戏运行
```

### 2. 关键连接点

#### 后端到前端的映射关系：
1. **Skills.config** → **SkillConf.json**
   - 技能基础信息同步

2. **SkillsLevel.config** → **SkillsLevelConf.json**
   - 技能等级信息同步

3. **SkillRanges.config** → **Monster.json**
   - 通过 `results.id` 连接到召唤物配置

4. **Monster.json** → **Props.json**
   - 通过 `propid` 连接到属性配置

### 3. 召唤神兽的完整流程

#### 服务器端逻辑：
1. 玩家释放召唤神兽技能 (ID: 30, Level: 1)
2. 服务器读取 `SkillsLevel.config` 获取 `actRange = {223}`
3. 服务器读取 `SkillRanges.config` 中ID 223的配置
4. 服务器执行 `results` 中的召唤逻辑：
   - `resultType=9`: 召唤类型
   - `id=129`: 召唤entityid为129的怪物
   - `value=1`: 召唤1只
   - `param1=5`: 持续时间5秒
   - `param2=20`: 其他参数

#### 客户端显示：
1. 客户端读取 `SkillsLevelConf.json` 显示技能描述
2. 客户端读取 `Monster.json` 获取召唤物外观 (modelid: 30150)
3. 客户端读取 `Props.json` 获取召唤物属性 (propid: 115)

## 修改建议

### 1. 血量修改
**需要同时修改前后端配置：**

**后端**: 修改 `SkillRanges.config` 中的参数
**前端**: 修改 `Props.json` 中的 `nMaxHpAdd` 值

### 2. 防御修改
**主要修改前端配置：**
- 修改 `Props.json` 中的防御相关属性

### 3. 造型修改
**主要修改前端配置：**
- 修改 `Monster.json` 中的 `modelid` 值

### 4. 技能描述修改
**主要修改前端配置：**
- 修改 `SkillsLevelConf.json` 中的 `skillDesc` 和 `skillNextDesc`

## 注意事项

1. **同步性**: 前后端配置必须保持同步，否则会出现显示和逻辑不一致
2. **格式差异**: 后端使用Lua格式，前端使用JSON格式
3. **缓存问题**: 前端配置修改后需要清除浏览器缓存
4. **服务器重启**: 后端配置修改后需要重启服务器
5. **测试验证**: 修改后需要同时测试前后端功能

## 总结

前后端配置是相互配合的：
- **后端配置**负责游戏逻辑计算和技能效果
- **前端配置**负责客户端显示和用户交互
- 两者通过ID关联，形成完整的技能系统

修改技能时，需要根据修改内容决定是否需要同时修改前后端配置，确保游戏逻辑和显示的一致性。
